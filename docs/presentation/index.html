Executive Brief

Executive Summary & Problem Definition

Slide 02 / 10
01

The Reservation Trilemma

High peak-hour concurrency in railway ticketing causes connection starvation, deadlocks, and accidental overbooking (double bookings) when isolation levels fail.

✔ Solution: MySQL 8 Row-Level Locking
02

The Polling Bottleneck

Thousands of passengers constantly refreshing browser tabs for live seat availability flood the transactional database with heavy repetitive read I/O queries.

✔ Solution: Firebase WebSocket Push Tree
03

Cross-Zonal Analytics

Running heavy regional aggregation and demand queries over nationwide historical booking logs severely degrades transactional checkout latency.

✔ Solution: Cosmos DB Partitioned by /region
Architectural Core: Transactional Outbox Pattern decouples relational writes from cloud sync. Reliability Target: 100% Zero-Overbooking

MySQL 8 (InnoDB)

Single source of truth for users, trains, inventory, and seat allocations.

Ultra-fast reactive WebSocket streams directly updating passenger screens.

  • •Data Model: Hierarchical JSON Tree
  • •Consistency: Monotonically versioned state
  • •Latency: Sub-second client updates
  • •Access Pattern: Direct WebSocket subscriptions
Zonal Telemetry NoSQL Doc

Horizontally scalable historical booking logs partitioned by railway zone.

  • •Data Model: Partitioned JSON Documents
  • •Partition Key: /region (North, West, South)
  • •Consistency: Bounded Staleness / Session
  • •Access Pattern: Analytics & geographical audit queries
Key Architectural Win: Eliminates both lock-contention & dual-write inconsistencies. Polyglot Persistence

Transactional Outbox Workflow (Zero Dual-Write Failure)

STEP 1: Atomic Commit Ticket booking, inventory decrement, and outbox event write execute inside one atomic MySQL transaction.
STEP 2: Outbox Worker Poller Asynchronous background CDC worker scans unpublished events (published = False).
STEP 3: Cloud Dispatch Worker pushes to Firebase & Cosmos DB with retry policies, setting published = True on success.
Guaranteed At-Least-Once Delivery to Cloud Projections Fail-Safe Isolation

users & stations

Schedules & intermediate station sequences.

  • • departure_datetime, arrival_datetime, status
  • • UQ: (train_id, travel_date)

journey_inventory

Class quotas & pessimistic locking target.

  • • journey_id (FK), travel_class ('AC' | 'GENERAL')
  • • capacity (10), available_seats, waitlist_count
  • • version: Optimistic Concurrency Token

tickets & passengers

Master PNR & individual seats.

  • • tickets: pnr (UQ), user_id, journey_id, total_fare
  • • passengers: seat_number, status ('CNF' | 'WL')
  • • waitlist_position: sequential FIFO index

booking_events (Outbox)

Transactional CDC audit & dispatch log.

  • • aggregate_id (PNR), event_type
  • • payload (JSON snapshot of entity)
  • • published (BOOLEAN), retry_count (INT)

Slide 06 / 10
ALGORITHM 01

Pessimistic Row-Level Booking

Prevents race conditions when remaining seats = 1.

// Acquire exclusive lock
inv = db.query(JourneyInventory)
  .filter(...)
  .with_for_update().one()

if inv.available_seats >= count:
  inv.available_seats -= count
  allocate_seats()
elif waitlist_has_space:
  allocate_waitlist(FIFO)
else: raise 400 (Cap Exceeded)
ALGORITHM 02

Waitlist Cascading on Cancellation

Instant seat reallocation & queue compaction.

// Lock inventory & locate WL 1
inv = get_inventory_for_update()
next_wl = find_earliest_wl_passenger()

if next_wl:
  // Auto-promote to Confirmed
  next_wl.reservation_status = 'CNF'
  next_wl.seat_number = vacated_seat
  inv.waitlist_count -= 1
  compact_remaining_wl_queue()
  publish_promotion_event()
ALGORITHM 03

Directional Intermediate Routing

Searches stops with sequence ordering.

// Aliased TrainStop instances
StopSource = aliased(TrainStop)
StopDest = aliased(TrainStop)

query = query.join(StopSource)
  .join(StopDest)
  .filter(
    StopSource.stop_sequence <
    StopDest.stop_sequence,
    StopSource.code == source,
    StopDest.code == destination
  )
Guaranteed Isolation: Eliminates Dirty Reads, Phantom Reads & Lost Updates. ACID Invariant

Zero-Trust Credential Defense

  • •Immutable Outbox Log: Complete transactional trail for compliance audits.
